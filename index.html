Enterprise Medallion Lakehouse Platform

LakeForge is a production-grade, metadata-driven framework for building, testing, validating, and governing mission-critical data pipelines on Databricks, Delta Lake, and Apache Spark.

Trust Engine Scoring

🚀 Getting Started

Get up and running with your first LakeForge pipeline in under 5 minutes. LakeForge runs seamlessly on Databricks notebooks, automated jobs, and local PySpark environments.

Step 1: Set Up Catalogs & Schemas

Run these commands in Databricks SQL Warehouse or a notebook to create target Unity Catalog namespaces:

sql
CREATE CATALOG IF NOT EXISTS bronze;
CREATE CATALOG IF NOT EXISTS silver;
CREATE CATALOG IF NOT EXISTS gold;
CREATE CATALOG IF NOT EXISTS monitoring;

CREATE SCHEMA IF NOT EXISTS bronze.raw;
CREATE SCHEMA IF NOT EXISTS bronze.quarantine;
CREATE SCHEMA IF NOT EXISTS silver.cleaned;
CREATE SCHEMA IF NOT EXISTS silver.dim;
CREATE SCHEMA IF NOT EXISTS gold.marts;
CREATE SCHEMA IF NOT EXISTS monitoring.logs;

Step 2: Scaffold a LakeForge Project

Use the LakeForge CLI to generate a standardized configuration folder:

bash
lakeforge init my_lakehouse
cd my_lakehouse
lakeforge validate configs --env dev

Step 3: Run the Ingestion & Quality Pipeline

python
from pyspark.sql import SparkSession
from lakeforge.ingestion import create_csv_loader
from lakeforge.bronze import create_bronze_writer
from lakeforge.dq.dq_engine import DQEngine

spark = SparkSession.builder.appName("LakeForge-Quickstart").getOrCreate()

# 1. Ingest Raw CSV
loader = create_csv_loader(spark)
df_raw = loader.load_csv("/Volumes/bronze/raw/landing/sales.csv", header=True)

# 2. Append Audit Metadata and write to Bronze
writer = create_bronze_writer(spark)
df_bronze = writer.add_audit_columns(df_raw, source_system="pos_system")
writer.write_to_bronze(df_bronze, target_table="bronze.raw.sales", mode="append")

# 3. Validate Data Quality and Quarantine Failures
rules = [
    {"rule_name": "order_id_not_null", "rule_type": "null_check", "column": "order_id", "threshold": 0.0},
    {"rule_name": "positive_amount", "rule_type": "range_check", "column": "amount", "min_value": 0.01}
]
dq_engine = DQEngine(spark=spark, rules=rules)
valid_df, quarantine_df = dq_engine.validate(df_bronze)

if quarantine_df.count() > 0:
    quarantine_df.write.format("delta").mode("append").saveAsTable("bronze.quarantine.sales_bad")

print(f"Pipeline executed! Clean rows: {valid_df.count()}, Quarantined rows: {quarantine_df.count()}")

Cluster-Scoped Library Setup

To enable LakeForge across your entire Databricks cluster:

  1. In your Databricks workspace, go to Compute ➔ Select your cluster.
  2. Click the Libraries tab ➔ Click Install New.
  3. Select PyPI and enter: git+https://github.com/jayarampogakula/Lakeforge.git
  4. Click Install.

💡 Concepts

1. Declarative Pipelines

No more fragile, hardcoded SQL scripts. Declare table connections, drift policies, DQ rules, and aggregations entirely in version-controlled JSON files.

2. Multi-Tenancy & Client Scoping

Pass --client <client_id> to override base ingestion or transformation rules for specific enterprise clients without duplicating code.

3. The Quarantine Pattern

Never let a single bad record crash an overnight batch. Bad records are routed to a quarantine table with failure metadata, while clean records continue to Silver and Gold.

4. Trust Score Formulation

The Trust Engine calculates a weighted score from 0% to 100% based on DQ pass rate, schema drift, row volume spikes, and key uniqueness.

💻 Command Line Interface (CLI)

The unified lakeforge CLI handles all pipeline execution, validation, and multi-stage deployments:

bash
# 1. Project Initialization
lakeforge init my_project

# 2. Configuration Validation
lakeforge validate configs --env dev
lakeforge validate configs --env prod --client client_alpha

# 3. Pipeline Execution
lakeforge run --layer bronze --name transactions --env dev
lakeforge run --layer silver --name customers_clean --source bronze.raw.customers --scd2
lakeforge run --layer gold --name daily_revenue --env prod
lakeforge run --layer governance --env prod --dry-run

# 4. Multi-Stage Deployment
lakeforge deploy --stage staging --dry-run
lakeforge deploy --stage prod --component all

Example: Gold Dimensional Aggregation

json
{
  "target_table": "gold.marts.daily_revenue",
  "source_tables": [
    {
      "alias": "t",
      "table": "silver.cleaned.transactions"
    },
    {
      "alias": "c",
      "table": "silver.dim.customers",
      "join_type": "inner",
      "join_condition": "t.customer_id = c.customer_id AND c.is_current = true"
    }
  ],
  "group_by": ["CAST(t.order_date AS DATE) AS sale_date", "c.country_code"],
  "metrics": [
    "COUNT(DISTINCT t.order_id) AS total_orders",
    "SUM(t.total_amount) AS total_gross_revenue"
  ],
  "z_order_columns": ["sale_date", "country_code"]
}

⭐ Best Practices

💡
Liquid Clustering: On DBR 13.3 LTS and higher, use Delta Liquid Clustering (CLUSTER BY) over legacy partition keys for high-cardinality multi-column filter acceleration.
🔒
Zero Hardcoded Credentials: Always store database passwords and tokens in Databricks Secret Scopes or Azure Key Vault and reference them in JSON configs.
⚠️
VACUUM Retention Window: Maintain at least 7 days (168 hours) of Delta log retention to safeguard concurrent readers and allow point-in-time rollbacks.

❓ Frequently Asked Questions (FAQ)

Q: How does LakeForge differ from Delta Live Tables (DLT)?

A: LakeForge is portable across standard PySpark, local Docker, and cloud clusters without DLT price premiums or vendor lock-in. It provides built-in multi-tenant config fallback, composite Trust Engine scoring, and CLI tooling.

Q: Can LakeForge run outside Databricks?

A: Yes! The core ingestion, bronze, silver, gold, and trust engines run on open-source PySpark and Delta Lake (locally, in Docker, or on AWS EMR / GCP Dataproc).

Q: What happens if a DQ rule fails?

A: LakeForge's Quarantine pattern isolates failed records into a separate quarantine table while clean records continue to Silver and Gold, avoiding pipeline interruptions.
